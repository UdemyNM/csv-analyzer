# 05. 画面設計（UIデザイン：案B 採用）

分析画面を3案（A：3ペイン / B：フィルタバー＋単一カラム / C：ビュー中心）で比較し、**案B**を採用した。
モックアップ: https://claude.ai/artifact/GRQmaAoPfrLiVujRj4D97Z （`PlanB.dc.html`。閲覧にはオーナーの共有が必要）

## 1. 採用理由
- 要件の流れ（フィルタ → 集計 → グラフ → 統計）が、上から下へ素直に並ぶ
- 〜10人・〜10MB規模ではデータ一覧が短く、左サイドバー（案A）は不要
- スマホ幅への対応が最も素直で、手戻りが少ない
- Recharts のコンポーネントを置きやすく、実装が単純

### 不採用案の扱い
| 案 | 見送った理由 | 将来の取り込み候補 |
|---|---|---|
| A: 3ペイン型 | 横幅が必要で、スマホで長くなる。一覧が短い規模では左ペインが余る | データ数が増えたら一覧のサイドバー化を検討 |
| C: ビュー中心型 | 設定が折りたたまれ、自分で分析を組み立てる操作が遠回り | ビューが増えたら、ビュー選択を「カード一覧」に置き換える |

## 2. 画面構成（詳細画面 `/datasets/:id`）
タブはやめ、**縦1列に4つのセクション**を上から並べる（2回目のデザイン修正）。各セクションの見出し右端に開閉ボタン（▼/▲）を置き、表示/非表示を切り替える。

```
┌ ヘッダー: ロゴ / データ一覧 / 利用者名 / ログアウト ───────────────┐
│ ← データ一覧に戻る                                               │
│ [アップロード直後だけ] 「アップロードしました」の帯              │
│ データセット名 [公開範囲バッジ][非公開にする] 行数・列数・文字コード・作成者 │
│                                  ビュー[選択▼] [ビューを保存]    │
├ フィルタバー: [条件チップ×] [＋条件を追加]      並べ替え[選択▼] ┤
├ ▼ データ表（フィルタ後の先頭N行＋ページング）          [開閉] ─┤
├ ▼ グラフ（X軸・Y軸・種類の選択つき）                    [開閉] ─┤
├ ▼ 集計（グループ化・指標の選択＋集計結果の表）          [開閉] ─┤
├ ▼ 統計・相関（基本統計の表／相関行列。用語に「？」解説）[開閉] ─┤
└──────────────────────────────────────────────────────────────────┘
```

### 他画面（案Bと同じ上部ナビを共通利用）
| 画面 | パス | 内容 |
|---|---|---|
| ログイン | `/login` | メール＋パスワードのみ（登録画面なし） |
| データ一覧＋アップロード | `/` | 上に**CSVのドロップ枠**（「ファイルを選ぶ」ボタンつき）、下に自分＋全員公開のデータ一覧（公開範囲バッジ・作成者） |

- **アップロード画面（`/upload`）はなくした**。一覧画面のドロップ枠にCSVを落とす（または「ファイルを選ぶ」）と、その場でアップロードして**新しい分析画面を開く**
- ドラッグ中は、ドロップ枠の枠線と色が変わり「ここで離すと、分析を始めます」と出す
- 分析画面の上部に、アップロード直後だけ「アップロードしました」の帯を出す
- スマホ幅ではドラッグ操作がないので、ドロップ枠の中の「ファイルを選ぶ」ボタンを大きく出す
- データセット名はファイル名を使う（変更は詳細画面。FR-14）。アップロード時の名前・公開範囲の入力欄はなくした。公開範囲は詳細画面のボタンで切り替える。**アップロード直後の既定値は「非公開」**（誤って共有しないため）。詳細画面には「公開にする」を出し、公開中は「非公開にする」を出す（モックは公開中の表示になっている）

## 3. セクション構成（03 の記述からの変更点）
- 03 では タブを「テーブル / 集計 / グラフ / 統計・相関」の4つとしていた
- 案Bの最初の修正で「集計」と「グラフ」を1つ（集計・グラフ）に統合して3タブにした
- **さらに、タブをやめて縦1列のセクション（データ表 → グラフ → 集計 → 統計・相関）にした。「集計」は「グラフ」から分けて、別セクションにした**
  - 理由: 絞り込んだ表を見ながら、その下でグラフ、集計、統計を、スクロールだけで追える。使わない部分は開閉ボタンで畳める
  - 「グラフ」と「集計」は同じ設定（グループ化・指標）を共有する（03 の 7 章）。集計をしたときはグラフの元データが集計結果になるので、集計セクションの設定を変えるとグラフも変わる
- フィルタ・並べ替えは**セクションの外（共通のフィルタバー）**に置き、全セクションに適用する
- 4つとも初期状態は「開いた状態」。開閉の状態は保存しない（画面を開き直すと全部開く）
- 集計セクションは、グループ化・指標の選択と、集計結果の表（1ページ100行のページング）を持つ。モックにも描いた（PC・スマホ）
- 03-functional-design.md の画面一覧とレイアウト図は、この内容に更新済み

## 5. 振る舞い
- フィルタ条件はチップで表示し、× で削除、「＋条件を追加」で列・演算子・値を選ぶ
- フィルタ・並べ替えの結果は、集計・グラフ・統計・テーブルのすべてに反映する
- ビュー保存時は、フィルタ・並べ替え・集計・グラフ設定（`views.config`）を保存する
- CSVを一覧のドロップ枠に落とす／「ファイルを選ぶ」で選ぶと、サイズ（10MBまで）・拡張子（.csv）・空を検証し、通れば保存して分析画面へ移る。通らなければ理由を枠の中に出し、移動しない
- 4つのセクションは、見出し（行全体）か右端の開閉ボタンで開閉する。開閉ボタンは `aria-expanded` を持つ実際のボタン（または `details`/`summary`）にする
- 基本統計の列見出し（件数・平均・中央値・標準偏差・最小・最大）と「相関行列」の見出しの横に「？」ボタンを置く。押すと表の下（相関は見出しの下）に短い解説を出し、もう一度押すか×で閉じる。解説は同時に1つだけ
  - 件数: 空欄を除いたデータの数 / 平均: 全部足して件数で割った値 / 中央値: 小さい順に並べた真ん中の値（極端な値に強い） / 標準偏差: 平均からのばらつきの大きさ / 最小・最大: 一番小さい・大きい値 / 相関: 2つの列が一緒に増減する強さ（−1〜1）
- 他メンバーのビューを開いた場合、設定の変更は自分の画面上だけ。保存できるのは自分のビューのみ
- 公開範囲の変更・削除は作成者にだけ表示する（権限はサーバー側でも強制）
- グラフの種類: 棒 / 折れ線 / 円 / 散布図
- データ表は先頭N行のプレビュー（行数はフィルタ後の件数を併記）。大量行はページングする
- 集計結果の表も、1ページ 100 行でページングする（グループ数が多いと描画が重いため。10MB・23万行の実測で、約1.9万グループが約0.8秒 → 約0.1秒）。集計は全行に対して行う
- グラフは 2,000 点を上限とし、超えるときは先頭を含めて等間隔に間引いて描き、グラフの下に「全 N 件のうち M 件を間引いて表示しています」と注記する（Recharts は 1点あたり約0.15〜0.45ms。散布図 1万点で約1.5〜4.6秒かかるため）

## 6. レスポンシブ
- 横幅の最大は 1120px で中央寄せ。余白は左右 24px
- 4つのセクションは常に縦1列。セクションの中で横に並ぶ部品は `flex-wrap` で並べ、狭い幅では縦に積む
- フィルタバー、ビュー選択、ヘッダーは折り返す
- 表は横スクロールの箱に入れ、ページ全体は横スクロールさせない
- 確認する幅: 375px（スマホ）/ 768px（タブレット）/ 1280px（PC）

## 8. アクセシビリティ
- ボタン・入力は実際の `button` / `select` / `input` + `label` を使う
- タッチ領域は 44px 以上
- 文字のコントラストは 4.5:1 以上
- 開閉セクションは、開閉ボタンに `aria-expanded` と `aria-controls` を付ける（`details`/`summary` なら標準の挙動を使う）。開閉ボタンのタッチ領域は 44px
- 「？」ボタンには「『標準偏差』とは」のような `aria-label` を付け、解説は `role="note"` で出す。閉じるボタンにも `aria-label` を付ける
- ドロップ枠はドラッグできない人のために、キーボードで押せる「ファイルを選ぶ」ボタン（または同等のリンク）を必ず持つ。ドラッグ中の変化は色だけでなく文言（「ここで離すと…」）でも伝える
- グラフは `role="img"` と `aria-label` を付け、同じ内容を集計表でも読めるようにする
- アイコンだけのボタンには `aria-label` を付ける
- 色だけで意味を伝えない（公開範囲はバッジの文字でも示す）

## 9. 実装時の注意（TDD）
- UIのテストは `tests/components/` に置く（`src/components/` と同じ階層）
- 先に書くテストの例: フィルタチップの追加・削除、セクションの開閉、「？」の解説の開閉、CSVのドロップ（正常／10MB超／.csv以外／空）、他人のデータで公開範囲の操作が出ないこと、狭い幅で表が横スクロールの箱に収まること
- Recharts の最新公式ドキュメントを確認してから `ChartView` を実装する（04 の Phase 5）
- この画面設計はモックアップの値（売上・地域など）を含むが、実際の列名はCSVごとに異なるため、**画面に列名を固定しない**
