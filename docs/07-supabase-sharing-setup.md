# 07. CSV 共有の設定手順（Phase 8b）

データ（datasets）・ビュー（views）・CSV 原本を Supabase に置き、ユーザー間で共有する。
テーブル・RLS・Storage のバケットとポリシーは `supabase/migrations/` の SQL で作る（ダッシュボードで手作業しない）。

> 前提: `docs/06-supabase-auth-setup.md` の手順が済んでいる（プロジェクト作成・サインアップ停止・ユーザー発行・`.env`）。
> コマンドとダッシュボードの画面名は 2026-11 時点の公式ドキュメントに基づく。

## 0. プロジェクト作成時の設定（確認）

| 項目                            | 設定                                            |
| ------------------------------- | ----------------------------------------------- |
| Enable Data API                 | オン                                            |
| Automatically expose new tables | **オフ**（GRANT は migration で明示する）       |
| Enable automatic RLS            | オン（migration でも RLS を明示的に有効にする） |

## 1. 何が作られるか

| 対象                | 内容                                                                                                                                                              |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `profiles`          | 作成者名の表示用。ユーザーの追加・表示名の変更で自動更新（トリガー）。ログイン中なら全員の表示名を読める                                                          |
| `datasets`          | 自分のもの＋全員公開（shared）だけ読める。更新・削除は作成者だけ。変更できる列は name / visibility だけ                                                           |
| `views`             | 親 dataset が見える人だけ読める・作れる。更新・削除は作成者だけ                                                                                                   |
| Storage `csv-files` | private バケット（10MB まで、text/csv のみ）。パスは `{作成者id}/{dataset id}.csv`。置く・消すは自分のフォルダだけ。読むのは自分のもの・見える dataset の原本だけ |

- 未ログイン（anon）には、どのテーブルにも権限を付けない
- 退職などでユーザーを削除すると、その人の datasets / views も消える（CSV 原本はバケットに残るので、必要なら Storage 画面で `{その人のid}/` を消す）

## 2. 本番に反映する（管理者・ターミナルで実行）

データベースのパスワード（プロジェクト作成時に保存したもの）を使う。**パスワードはチャットやファイルに貼らない。**

1. Supabase CLI にログインする（ブラウザが開く）

```bash
npx supabase login
```

2. このフォルダを本番プロジェクトに結びつける（`<project-ref>` はダッシュボードの URL の `https://supabase.com/dashboard/project/<project-ref>` の部分）

```bash
npx supabase link --project-ref <project-ref>
```

3. 反映される内容を確かめる（実際には変更しない）

```bash
npx supabase db push --remote --dry-run
```

4. 反映する

```bash
npx supabase db push --remote
```

- CLI v3 の `db push` は、何も付けないと手元の Docker（ローカル環境）に反映しようとする。本番には必ず `--remote` を付ける

5. ダッシュボードで確かめる
   - Table Editor: `profiles` / `datasets` / `views` があり、どれも RLS が有効（「RLS disabled」の表示が無い）
   - `profiles` に、発行済みのユーザーが入っている
   - 表示名は `app_metadata.display_name` から取る（docs/06 の手順 3 の 4）。無いユーザーは、他の人の画面で「不明なユーザー」になる（メールアドレスは `profiles` に入れない）。
     以前 `user_metadata` に表示名を入れていた場合は、`app_metadata` に付け直す
   - Storage: `csv-files` があり、Public になっていない

## 3. GitHub Pages（本番サイト）に反映する

- 接続設定（GitHub の Variables）は docs/06 の手順 5 のまま。追加は無い
- PR を main にマージすると、`deploy.yml` が公開サイトを更新する
- **migration（手順 2）を先に反映してからマージする。** 逆にすると、公開サイトで一覧の取得やアップロードが失敗する

## 4. 共有の動作確認（ユーザー 2 人で）

ユーザー A・B を用意し、別のブラウザ（またはシークレットウィンドウ）でそれぞれログインする。

| #   | 操作                                                        | 期待する結果                                                     |
| --- | ----------------------------------------------------------- | ---------------------------------------------------------------- |
| 1   | A が CSV を「非公開」でアップロード                         | A の一覧に出る。B の一覧には出ない                               |
| 2   | B が、A の非公開データの URL（`#/datasets/<id>`）を直接開く | 「見つかりません」                                               |
| 3   | A がそのデータを「公開」にする                              | B の一覧に出て、開くと分析できる。作成者名に A の表示名が出る    |
| 4   | B が A の公開データの名前変更・削除を試す                   | 操作できない（ボタンが出ない、または権限エラー）                 |
| 5   | B が A の公開データでビューを保存する                       | A にも B のビューが見える。A は B のビューを変更・削除できない   |
| 6   | A がデータを「非公開」に戻す                                | B の一覧から消え、URL を開いても「見つかりません」               |
| 7   | A がデータを削除する                                        | 一覧から消える。Storage の `csv-files/<Aのid>/` から原本も消える |

- 1 つでも期待と違えば、公開を止めて（一覧の公開を戻す・該当 PR を差し戻す）原因を調べる

## 5. 無料プランの注意

- DB 500MB・Storage 1GB・1 ファイル 50MB（アプリは 10MB まで）・転送量 5GB/月
- **1 週間アクセスが無いとプロジェクトが一時停止する。** ダッシュボードの「Restore」で再開できる（データは残る）

## 6. 以前のデータ（IndexedDB）

- Phase 8b より前に各ブラウザの IndexedDB に保存したデータは、移行しない（アプリからは見えなくなる）
- 必要な CSV は、各自アップロードし直す
