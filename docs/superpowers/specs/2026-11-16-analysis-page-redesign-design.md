# 分析画面の改修 設計書（2026-11-16）

対象: データセット詳細（分析）画面 `/datasets/:id`（`src/components/datasets/DatasetDetailPage.jsx` とその部品）

## 1. 目的（なぜ）

今の分析画面は「＋条件を追加」で列・演算子・値をフォームで選び、グラフ・集計もセレクトボックスで組み立てる。
これを、Excel のオートフィルタ・ピボットテーブル・ピボットグラフに近い **直接操作** に変え、
表を見ながら、その場で絞り込み・集計・グラフ化できるようにする。

## 2. ゴール / やらないこと / 失敗とみなすこと

### ゴール

1. 「＋条件を追加」をなくし、データ表の **列見出しのボタン（▼）** から、絞り込み・並べ替え・列の非表示を行う
   - 絞り込みは「値から選ぶ（複数選択）」か「自由入力（演算子＋値）」を選べる
2. データ表の **行と列を非表示** にできる（行は分析からも除く。列は見た目だけ）
3. 配置を **左＝データ表、右上＝グラフ、右下＝集計** にする
4. 集計を **ドラッグ＆ドロップで組み立てるピボット**（行・列・値の 3 つの枠）にする
5. グラフを **ピボットグラフ型** にする（集計の行＝X軸、列＝系列、値＝Y軸）。種類はボタンで選ぶ。散布図だけは元データを描く
6. 統計・相関は **初期状態で閉じる**

### やらないこと（今回の範囲外）

- ピボットの「フィルター」枠（絞り込みはデータ表の見出しで行う）
- ピボットの総計・小計
- 日付の列を年・月ごとにまとめてピボットに置く機能（今は日付の値そのものがキーになる）
- 集計結果の表での行・列の非表示
- 表と右側パネルの境目をドラッグして幅を変える機能
- グラフをクリックして絞り込む（ドリルダウン）

### 失敗とみなすこと（動いても NG）

- 25 万行（10MB）のデータで、操作のたびに画面が 1 秒以上固まる
- 既存の保存済みビューが開けなくなる・設定が黙って消える
- マウスなし（キーボードのみ）やスマホのタッチで、絞り込み・ピボット・グラフの操作ができない

## 3. 制約

- React 19 / Vite / Vitest + React Testing Library / Recharts 3（既存）
- ドラッグ＆ドロップには **@dnd-kit** を新しく追加する（ユーザー承認済み）。実装前に最新の公式ドキュメントを確認し、
  `@dnd-kit/core` 系と新しい `@dnd-kit/react` 系のどちらを使うかを、計画の段階で決めて伝える
- TDD（Red → Green → Refactor）。テストは `tests/` 以下、`src` と同じ階層
- 性能の基準は今と同じ（docs/03 7 章・docs/05 5 章）: 10MB・約 25 万行でフィルタ約 0.1 秒、集計 0.1〜0.5 秒、グラフは 2,000 点に間引く
- 元の CSV は変更されない（データセットの `update` は名前・公開範囲だけ）。行の「元の行番号」は安定した ID として使える
- 画面に列名を固定しない（CSV ごとに列が違う）
- アクセシビリティは docs/05 8 章に従う（実際の button/input、タッチ領域 44px、aria-label など）

## 5. 画面構成

### 5.1 配置

```
┌ ヘッダー（今のまま）──────────────────────────────────────────────┐
│ ← データ一覧に戻る / データセット見出し / ビュー選択・保存（今のまま）│
├ フィルタバー: [店舗: 新宿店, 渋谷店 ×][売上 ≥ 1000 ×][非表示の行 3件 ×]   │
│              [非表示の列: 単価 ×]                  [すべて解除]       │
├──────────────────────────────┬────────────────────────────┤
│ ▼ データ表                     │ ▼ グラフ                      │
│ [👁][日付▼][店舗▼][商品▼][売上▼]│ [棒][折れ線][円][散布図]        │
│ [👁] 2024-01-01 新宿店 …        │ X軸[店舗 ×] 系列[商品 ×] Y軸[売上・合計 ×]│
│ …（縦スクロール・見出し固定）     │ （グラフ本体）                  │
│ 前へ 1/11 次へ                 ├────────────────────────────┤
│                              │ ▼ 集計（ピボット）              │
│                              │ 列名: [日付][店舗][商品][数量]… │
│                              │ 行[店舗] 列[商品] 値[売上・合計]   │
│                              │ （集計結果の表）                │
├──────────────────────────────┴────────────────────────────┤
│ ▶ 統計・相関（初期は閉じる・全幅）                                  │
└────────────────────────────────────────────────────────────┘
```

- **1024px 以上**: CSS Grid で 2 列。左（データ表）: 右（グラフ・集計）＝ 約 3:2。データ表は 2 行ぶんの高さを占める。
  横幅の上限を 1120px → **1600px** に広げる（このページだけ）
- データ表は、箱の中で縦にスクロールし、見出しを固定する（`position: sticky`）。箱の高さは右側の 2 つに合わせるか、画面の高さを上限にする（実装で決めてよい）
- **1024px 未満**: 縦 1 列（データ表 → グラフ → 集計 → 統計・相関）。ページ全体は横スクロールさせない
- 4 つのセクションはどれも今の `CollapsibleSection` で開閉できる。**統計・相関だけ初期状態で閉じる**（`defaultOpen` のような prop を足す）。開閉の状態は保存しない

### 5.2 フィルタバー（今の `FilterBar` を作り替え）

- 「＋条件を追加」と並べ替えの欄を **なくす**
- 残すもの: 条件のチップ（× で 1 つずつ外す）
- 足すもの:
  - 「非表示の行 N件 ×」のチップ（× ですべての行を表示に戻す）
  - 「非表示の列: 列名 ×」のチップ（列ごと。× でその列を表示に戻す）
  - 「すべて解除」ボタン（絞り込み・行の非表示・列の非表示をすべて戻す。並べ替えは残す）
- チップの表示: `in` は「店舗: 新宿店, 渋谷店」。値が 3 つを超えたら「店舗: 新宿店, 渋谷店 ほか 3 件」
- 何もないときは、フィルタバーに「列見出しの ▼ から絞り込めます」と薄く出す

## 6. データ表

### 6.1 列見出しのメニュー

各列見出しに ▼ ボタン（`aria-label="「店舗」の列のメニュー"`）を置く。押すとポップオーバーを開く。

```
┌ 店舗 ───────────────────┐
│ ↑ 昇順  ↓ 降順  並べ替えを解除  │
│ ─ 絞り込み ─────────────── │
│ (●) 値から選ぶ  ( ) 自由入力    │
│ [検索…              ]        │
│ [✓] すべて選択               │
│ [✓] 新宿店   (412)           │
│ [✓] 渋谷店   (380)           │
│ [ ] 池袋店   (301)           │
│ [適用] [キャンセル]            │
│ ─────────────────────── │
│ この列を非表示                │
└─────────────────────────┘
```

- **並べ替え**: 昇順・降順・解除。並べ替えは 1 列だけ（今と同じ）。並べ替え中の列は見出しに ▲/▼ を出す
- **値から選ぶ**:
  - 候補は「行の非表示・ほかの列の条件をかけたあとの行」から作る（この列の `in` 条件は除いて数える。Excel と同じ）
  - 値ごとの件数を出す。件数の多い順に、**最大 1,000 種類** まで出す。それより多いときは「ほか N 種類。検索で絞り込んでください」と出し、検索は全種類から探す
  - 空欄は「（空欄）」として選べる
  - 「すべて選択」「すべて解除」あり。検索中の「すべて選択」は、検索に合う値だけを対象にする
  - 「適用」で、この列の「値から選ぶ」条件（`in` / `notIn`）を **置き換える**（すでにあれば差し替え、0 個なら適用できない）
  - 「全部」は、今の候補の全種類（1,000 種類の上限より先の値も含む）を指す。全部選んだら条件を外す
  - 保存する形は、**選んだ値と外した値の少ないほう**にする（設計者の判断。種類の多い列で、少しだけ外すと `values` に数万件が入るのを防ぐ）
    - 選んだ値のほうが少ない → `in`（選んだ値だけを残す。あとで現れた値は含まない）。チップ「店舗: 新宿店, 渋谷店」
    - 外した値のほうが少ない → `notIn`（外した値だけを除く。あとで現れた値は含む）。チップ「店舗: 池袋店 以外」
    - 同数なら `in`
  - メニューを開き直したとき、`in` は選んだ値に、`notIn` は外した値以外にチェックを付けて出す
- **自由入力**: 演算子（今の 7 種: = ≠ を含む > ≥ < ≤）＋ 値。「追加」で条件を **足す**（同じ列に複数可。例: ≥ 1000 と ≤ 5000）。
  不正な条件（文字列の列に > など）は今と同じく `InvalidFilterError` で、メニューの中にエラーを出して閉じない
- **この列を非表示**: 列を表から隠す（6.3）
- 条件のある列は、見出しの ▼ ボタンの見た目を変える（色だけでなくアイコンも変える）
- キーボード: Esc で閉じて ▼ ボタンにフォーカスを戻す。開いたら最初の操作できる部品にフォーカスする。外側をクリックしたら閉じる

### 6.2 行の非表示

- 各行の左端に「この行を非表示」ボタン（アイコン。`aria-label="3 行目を非表示"`。行番号は元の CSV の行番号）
- 非表示の行は、データ表・グラフ・集計・統計・相関の **すべてから除く**
- 処理の順番: **元の行 → 非表示の行を除く → 絞り込み → 並べ替え**
- 行は「元の行番号」（CSV のデータ行の 0 始まりの添字）で覚える。並べ替え・絞り込み後の行からも元の行番号が分かるようにする（作り方は実装で決めてよい。例: 読み込み時に行オブジェクト → 添字の `WeakMap`、または行番号の配列を一緒に持ち回す）
- 25 万行で、非表示の行を除く処理が 0.1 秒を超えないこと

### 6.3 列の非表示

- 見た目だけ。データ表から列を隠す。絞り込み・集計・グラフ・統計には影響しない
- 隠した列も、ピボットの列名一覧からはドラッグできる。隠した列にかかった条件はチップに残る

## 7. 集計（ピボット）

### 7.1 操作

- パネルの上に **列名の一覧**（ドラッグ元。全列。隠した列も含む）
- その下に 3 つの枠: **行** / **列** / **値**
- ドラッグ元: 列名の一覧、データ表の列見出し（見出しの文字の部分。▼ ボタンは除く）
- 枠の中のチップは、ドラッグで **並べ替え・ほかの枠への移動** ができる。× で外す。枠の外へドラッグしても外れる
- 同じ列を「行」と「列」の両方には置けない（置いたら、元の枠から移動する）。「値」には、行・列に置いた列も置ける（件数を数えるときなど）
- **値** に落としたとき: 数値の列なら「合計」、それ以外の列なら「件数」にする。チップ（例「売上・合計 ▼」）を押すと、
  合計・平均・件数・最小・最大を選べる（数値でない列は件数だけ）。同じ列・同じ関数は二重に置けない
- キーボード・スマホ用に、各枠に「＋」ボタンを置き、押すと列名の一覧から選べる（ドラッグしなくても全操作ができる）。
  あわせて @dnd-kit のキーボード操作・タッチ操作も有効にする

### 7.2 計算

- 入力: 「非表示の行を除く → 絞り込み → 並べ替え」後の行
- 行の枠のキーでグループ化し、列の枠のキーで横に展開し、各セルに値の枠の集計を入れる
- 行の並び: 各グループが最初に現れた順（今の `aggregate` と同じ。データ表の並べ替えが効く）
- 列の並び: 列のキーを **昇順**（列の型に合わせて、数値・日付・文字列で比べる）。複数の列を置いたときは、左の列から順に入れ子にする
- 列のキーの組み合わせが **50 を超えたら** 先頭 50 だけを表に出し、「列が多いため、先頭 50 列だけを表示しています（全 N 列）」と注記する
- 値が 1 つもないとき: 集計しない（表もグラフも出さず、「値の枠に列を置くと集計します」と出す）
- 行・列が空で値だけあるとき: 全体を 1 行に集計する
- 集計関数の意味は今の `aggregate` と同じ（件数＝行数。合計・平均・最小・最大は数値として読めた値だけ）
- 今の `utils/aggregate.js` を拡張するか、新しい純粋関数（例 `utils/pivot.js`）にするかは実装で決めてよい。どちらにしても純粋関数で、単体テストを書く

### 7.3 集計結果の表

- 列の枠が空なら、今と同じ 1 段の見出し（行のキー列 ＋ 値の列）
- 列の枠があれば、見出しを 2 段以上にする（上の段: 列のキー、下の段: 値の名前）。値が 1 つだけなら、値の段は省いてよい
- 1 ページ 100 行のページング（今と同じ）
- この表では、行・列の非表示はしない

## 8. グラフ（ピボットグラフ）

### 8.1 種類の選び方

- 種類はボタン（棒・折れ線・円・散布図）。選んでいるものは `aria-pressed="true"`
- 初期値は棒

### 8.2 棒・折れ線・円

- グラフパネルにも 3 つの枠: **X軸** / **系列** / **Y軸**。これらは集計の **行 / 列 / 値** と同じもの（どちらで操作しても、両方に反映する）
- 描くデータは集計の結果:
  - X 軸のラベル: 行のキー（複数なら「新宿店 / りんご」のように「 / 」でつなぐ）
  - 系列: 列のキーの組み合わせ × 値（値が 1 つなら列のキーだけ。列が空なら値ごとに 1 系列）
  - 系列の上限は今の色の数（8）。超えたら先頭 8 系列だけ描き、注記を出す
- 円グラフ: 最初の 1 系列だけ描く。系列が 2 つ以上あるときは「円グラフは最初の系列（○○）だけを描いています」と注記する
- 2,000 点の間引き、X 軸ラベルの間引きは今の `ChartView` の仕組みを使う
- 値がないときは「Y軸（集計の値）に列を置くと、グラフを表示します」と出す

### 8.3 散布図

- 散布図を選んだときだけ、枠を **X軸 / Y軸**（数値の列だけ受け付ける）に替える。これは集計とは別の設定
- 描くデータは「非表示の行を除く → 絞り込み」後の元の行。2,000 点に間引く（今と同じ）
- 散布図から棒などに戻すと、集計の枠（行・列・値）の表示に戻る。散布図の X/Y は覚えておく

## 9. 設定の形（`views.config`）と保存済みビュー

### 9.1 新しい形

```js
{
  filters: [
    { column, op: "eq" | "ne" | "contains" | "gt" | "gte" | "lt" | "lte", value: string },
    { column, op: "in", values: string[] },   // 新規。空欄は "" で表す
    { column, op: "notIn", values: string[] }, // 新規。values に含まれる行を除く（6.1）
  ],
  sort: { column, direction: "asc" | "desc" } | null,
  hiddenRows: number[],      // 新規。元の行番号（0 始まり）
  hiddenColumns: string[],   // 新規
  pivot: {                   // aggregation を置き換え
    rows: string[],
    columns: string[],
    values: { column?: string, fn: "sum" | "avg" | "count" | "min" | "max" }[],
  } | null,
  chart: {
    type: "bar" | "line" | "pie" | "scatter",
    scatter: { x: string, y: string } | null,
  } | null,
}
```

- `filterRows` に `in`（`values` に含まれれば一致）と `notIn`（含まれなければ一致）を足す
- `pivot` は 3 つの枠がすべて空なら `null`

### 9.2 古い形のビューの読み込み

`sanitizeConfig`（`components/views/viewConfig.js`）で、古い形を新しい形に変換してから、今と同じ「データにない列は無効にして警告」を行う。

| 古い形                                      | 新しい形                                                                                                                                                              |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `aggregation: { groupBy, metrics }`         | `pivot: { rows: groupBy, columns: [], values: metrics }`                                                                                                              |
| `chart: { type: "scatter", x, y }`          | `chart: { type: "scatter", scatter: { x, y } }`                                                                                                                       |
| `chart: { type: 棒など, x, y }`（集計あり） | `chart: { type, scatter: null }`。軸は集計で決まるので x/y は捨てる。古いグラフで Y が指標の 1 つだけでも、新しいグラフでは集計の全部の値が系列になる（設計者の判断） |
| `chart: { type: 棒など, x, y }`（集計なし） | 集計に変換する: `pivot: { rows: [x], columns: [], values: [{ column: y, fn: "sum" }] }`、`chart: { type, scatter: null }`（設計者の判断）                             |
| `hiddenRows` / `hiddenColumns` がない       | `[]`                                                                                                                                                                  |

- 集計なしのグラフを集計に変換したときは、黙って変えずに、ビューの警告欄（今の `viewWarning`）に「グラフの設定を集計（行＝○○、値＝△△の合計）に変換しました」と出す（2 章の「黙って消える」を避けるため）
- `hiddenRows` のうち、行数を超える番号は捨てる（警告は不要）
- `hiddenColumns`・`pivot` の各枠・`scatter` の列がデータにないときは、今と同じく無効にして警告に含める
- 変換は読み込み時だけ。保存すると新しい形で上書きされる

## 11. テスト（TDD）

先に失敗するテストを書く。最低限、次を含める。

- `filterRows`: `in`・`notIn`（複数値・空欄・存在しない列）
- ピボットの計算: 行だけ / 行＋列 / 値だけ / 列の昇順（数値・日付・文字列）/ 50 列の上限 / 関数 5 種
- `sanitizeConfig`: 古い形の変換、データにない列の無効化、`hiddenRows` の範囲外
- 列見出しのメニュー: 開閉・Esc・フォーカス、値から選ぶ（検索・件数・すべて選択・1,000 種類の上限・置き換え）、自由入力（追加・エラー）、並べ替え、列の非表示
- 行の非表示: 表・集計・統計から除かれる、チップで戻る
- フィルタバー: チップ表示、「すべて解除」
- ピボット: ＋ボタンでの追加・移動・削除、値の関数の変更、数値でない列は件数だけ（ドラッグそのものは、@dnd-kit のキーボード操作でテストできるなら書く。jsdom で無理なら ＋ ボタンの操作で代える）
- グラフ: 種類ボタン、共通の枠（グラフで置くと集計にも出る）、系列、円の注記、散布図の枠
- 統計・相関が初期で閉じている
- 保存済みビュー: 新しい形で保存され、開き直すと同じ状態になる
- 性能: 既存の `analysisPerformance.test.jsx` などの基準を壊さない。行の非表示・値の候補の計算を 25 万行で測る
- 既存のテストのうち、なくなる UI（「＋条件を追加」、並べ替えのセレクト、グループ化のチェックボックス、軸のセレクト）に依存するものは、新しい操作に書き換える
